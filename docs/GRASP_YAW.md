# 물체 방향에 맞춰 손목을 돌려 잡기 — 구현 설명서

목표 지점에 도착한 뒤, 손목 카메라(D435i)로 물체의 **긴 축**을 측정해
그리퍼가 그 축을 **가로질러** 닫히도록 손목을 회전시킨다.

구현 파일: `pick_and_place_voice/robot_control/webcam_pick_place.py`
관련 함수: `_d435_find_target()` → `_grasp_mask_geometry()` → `_grasp_yaw()` → `_job_refine_grasp()`

---

## 1. 왜 필요한가

RG2 그리퍼의 손가락은 **한 방향으로만** 열린다. 홈 자세에서 개폐축은
베이스 +X 방향이다(카메라로 손가락 끝 두 점을 역투영해 실측).

망치처럼 긴 물체를 그 축과 **나란히** 잡으면 손가락이 물체의 길이 방향을
따라 미끄러지며 헛돈다. 반드시 긴 축에 **수직으로** 물려야 한다.

---

## 2. 3단계 파이프라인

### 2-1. 물체의 픽셀만 골라내기 — 깊이 기반 분할

YOLO 바운딩 박스는 사각형이라 물체가 아닌 배경도 포함한다. 특히 **L자형
물체(망치)** 는 박스 중심이 머리와 손잡이 **사이의 빈 공간**에 떨어진다.
실제로 그 틈을 물어 망치를 회전시킨 실패 사례가 있었다.

그래서 박스 안에서 깊이 영상으로 물체 픽셀만 분리한다:

1. 박스 테두리(3 px)의 깊이 중앙값 = **배경(작업대) 높이**
2. 유효 깊이의 5 백분위수 = **가장 가까운 표면**
3. 분리 임계값 `cut = max(8 mm, 0.35 × (배경 − 최근접))`
4. `배경 − cut` 보다 가까운 픽셀 = **물체 마스크**

상대 비율(0.35)과 절대 하한(8 mm)을 함께 쓴다. 높은 물체는 비율이,
납작한 물체는 절대값이 기준이 된다. 분리에 실패하면(완전히 납작한 물체)
`None`을 반환하고 박스 중심으로 되돌아간다 — **추측하지 않는다.**

| 상수 | 값 | 의미 |
|---|---|---|
| `MASK_BORDER_PX` | 3 px | 배경 추정용 테두리 폭 |
| `MASK_HEIGHT_RATIO` | 0.35 | 물체 높이의 상대 임계 |
| `MASK_MIN_SEPARATION_MM` | 8 mm | 절대 최소 분리 |
| `MASK_MIN_PIXELS` | 30 px | 이보다 적으면 마스크 무효 |

### 2-2. 긴 축 구하기 — `cv2.minAreaRect`

마스크 픽셀 집합에 **최소 면적 회전 사각형**을 씌운다. OpenCV가 돌려주는
각도는 "첫 번째 변" 기준이므로, 가로가 세로보다 짧으면 **+90°** 해서
항상 **긴 변**의 각도가 되게 보정한다.

동시에 마스크의 **무게중심**을 파지 중심으로 쓴다 (박스 중심이 아니라).
L자형 물체에서 손가락이 실체 위로 가게 하는 핵심이다.

### 2-3. 이미지 각도 → 베이스 좌표계 각도

이미지에서 잰 각도는 카메라가 기울어져 있으면 그대로 쓸 수 없다. 그래서
**두 점을 역투영**해 실제 3D 방향을 구한다:

```
중심에서 긴 축 방향으로 ±40 px 떨어진 두 점 p1, p2 를
같은 깊이로 베이스 좌표계에 역투영
axis = p1[:2] − p2[:2]                      # 베이스 XY 평면상의 긴 축
long_angle = atan2(axis.y, axis.x)
yaw = long_angle + 90° − FINGER_AXIS_HOME_DEG
```

`+90°` 가 "긴 축에 **수직**으로 물린다"는 요구를 그대로 표현한다.

**±90°로 감기(wrap)**: 그리퍼는 180° 회전하면 자기 자신과 같다(대칭).
따라서 `+170°` 회전 대신 `−10°` 회전이면 충분하다. 손목이 불필요하게
크게 돌아 관절 한계나 특이점에 가까워지는 것을 막는다.

```python
while yaw >  90: yaw -= 180
while yaw < -90: yaw += 180
yaw = clip(yaw, -90, +90)
```

## 3. 로봇 자세에 적용 — J6만 도는 이유

파지 자세는 ZYZ 오일러각 `(rx, ry, rz)`으로 표현된다. 이 표현에서
**베이스 Z축 회전을 앞에 곱하는 것은 첫 번째 각도에 더하는 것과 정확히
같다.** 그래서 적용은 한 줄이다:

```python
grasp_orientation = (rx + yaw, ry, rz)
```

파지 직전 자세는 **툴이 바닥과 직각(top-down)** 이므로, 이 상태에서
베이스 Z 회전은 곧 **툴 축 회전**이고, 역기구학은 이를 대부분 **J6**의
회전으로 푼다. 겉보기에 "6번 관절만 돌아 물체 방향에 맞추는" 동작이 되는
이유가 이것이다. J1~J5는 위치를 유지하고, 손목 끝만 정렬한다.

> `--free-wrist` 모드로 접근한 경우 도착 시 몇 도의 잔여 기울기가 남을 수
> 있다. 그래서 yaw를 적용하기 전에 **툴을 먼저 수직으로 정렬**한다.
> 그러지 않으면 "top-down 상태에서의 Z회전"이라는 전제가 깨진다.

## 4. 같은 클래스가 여러 개일 때

정밀정렬 단계에서 같은 종류가 여러 개 보이면 **점수가 가장 높은 것**이 아니라,
웹캠 3대로 삼각측량해 둔 **그 개체**를 고른다. 목표 3D 좌표를 손목 카메라
영상에 투영한 뒤, 그 픽셀에 **가장 가까운 검출**을 선택한다. 접근 도중
다른 개체로 목표가 바뀌는 것을 막는다.

## 5. 요약 (PPT용)

1. **문제**: 그리퍼는 한 축으로만 열린다 → 긴 물체는 반드시 축에 수직으로 물려야 한다
2. **깊이 기반 마스킹**: 박스 테두리 중앙값을 배경으로 삼아 물체 픽셀만 분리
   (상대 35% + 절대 8 mm 이중 임계) → L자형 물체의 "빈 틈 파지" 실패 제거
3. **긴 축 추출**: `minAreaRect`로 회전 사각형을 씌우고 항상 긴 변 각도로 정규화,
   무게중심을 파지점으로 사용
4. **좌표 변환**: 이미지 각도를 그대로 쓰지 않고 축 위 두 점을 3D로 역투영해
   베이스 좌표계의 실제 방향을 계산 (카메라 기울기 무관)
5. **yaw = 긴 축 각도 + 90°**, 그리퍼 180° 대칭성을 이용해 ±90°로 감아
   손목 회전량 최소화
6. **적용**: ZYZ 자세의 첫 각도에 더하는 한 줄 — top-down 자세에서 이는
   J6 회전으로 풀린다
7. **분리 실패 시 추측하지 않고** 박스 중심으로 안전하게 되돌아간다
