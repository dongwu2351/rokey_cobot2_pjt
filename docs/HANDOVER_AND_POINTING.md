# 손에서 받아 정리하기 · 손가락 레이저 타겟팅 — 구현 설명서

DUM-E 프로젝트의 두 기능에 대한 기술 문서입니다. PPT 작성을 위한 원본 자료로,
실제 소스 코드에서 확인한 값만 담았습니다.

- **기능 A — 손에서 받아 빈 곳에 놓기**: 작업자가 손바닥에 올린 물건을 로봇이
  받아서, 작업대의 빈 자리를 스스로 찾아 내려놓는다.
  (`M` 키 또는 음성/채팅 "이거 가져다 놔")
- **기능 B — 손가락 레이저 타겟팅**: 검지로 가리키면 그 방향으로 3D 광선이
  뻗어나가, 가리킨 물체나 지점을 로봇의 목표로 확정한다.

## 1. 공통 기반: 웹캠 3대 삼각측량

두 기능 모두 "픽셀 → 3D 좌표" 변환 위에 서 있다.

각 카메라의 캘리브레이션에서 픽셀 하나는 **3D 광선** 하나가 된다. 카메라 N대의
광선들에 대해 최소제곱으로 교점을 구한다. 광선 `i`의 원점을 `oᵢ`,
방향 단위벡터를 `dᵢ`라 하고 `Pᵢ = I − dᵢdᵢᵀ`(광선에 수직인 투영행렬)이라 하면
교점 `p`는

```
(Σ Pᵢ) p = Σ Pᵢ oᵢ
```

의 해다. 여기서 중요한 설계는 **정직성 지표(honesty metric)** 다: 해를 구한 뒤
각 광선과 `p` 사이 거리를 재고, 그 **최댓값(worst gap)** 을 함께 반환한다.
이 값이 크면 카메라들이 서로 다른 것을 보고 있다는 뜻이므로 결과를 **버린다**.

- 물체 삼각측량 게이트: worst gap **40 mm** 초과 시 폐기
- 손가락 삼각측량 게이트: worst gap **35 mm** 초과 시 폐기
  (`pointing.py`, 주석: *"손가락은 작다. 뷰들이 손가락 굵기보다 더 어긋나면
  같은 손가락을 보고 있는 것이 아니다"*)

이 한 줄의 게이트가 "그럴듯한 오답"을 구조적으로 차단한다.

## 2. 기능 B — 손가락 레이저 타겟팅

### 2.1 검지에서 광선 만들기

`webcam_rig.py`가 MediaPipe Hands로 손을 찾고, 랜드마크 중 **검지 손허리관절
(INDEX_MCP = 5)** 과 **검지 끝(INDEX_TIP = 8)** 의 픽셀 좌표를 카메라마다 뽑는다.

```python
INDEX_MCP, INDEX_TIP = 5, 8
POINT_EXTENSION_RATIO = 1.25
```

**가리키는 제스처인지 판별**: 검지 끝까지의 거리가 접힌 손가락들의 거리보다
`1.25`배 이상 길면 "펴서 가리키는 중"으로 본다. 주먹을 쥐거나 물건을 잡은
손은 광선을 만들지 않는다.

`pointing.pointer_ray()`가 두 관절을 각각 삼각측량해 3D 점 두 개를 얻고,

- **원점** = 검지 끝 (손끝에서 광선이 나가야 사람이 보는 것과 일치)
- **방향** = (끝 − 관절) 정규화

로 광선을 만든다. 관절–끝 구간이 **35 mm** 미만이면(손가락이 카메라 쪽을 향해
짧게 보이는 경우) 방향 오차가 커지므로 거부한다.

### 2.2 무엇을 가리켰는가 — 거리가 아니라 **각도**

핵심 설계 결정이다. `pointing.py` 도입부에 근거가 적혀 있다:

> *"팔 길이 거리에서 공구로부터 3 cm 벗어난 손가락은 그 공구를 가리킨 것이다.
> 작업대 반대편 끝에서의 같은 3 cm는 옆 물건을 가리킨 것이다. 사람이 조절하는
> 것도, 관찰자가 읽는 것도 각도이므로, 매칭도 각도로 해야 한다."*

물체 위치 `q`에 대해

```
forward = (q − origin) · d                     # 광선을 따라 얼마나 앞인가
perp    = ‖(q − origin) − forward·d‖           # 광선에서 얼마나 빗겨났나
angle   = atan2(perp, forward)
```

판정 기준:

| 상수 | 값 | 의미 |
|---|---|---|
| `MAX_POINT_ANGLE_DEG` | 22° | 이보다 벌어지면 "가리켰다"고 하지 않는다 |
| `MIN_FORWARD_MM` | 40 mm | 손끝 **뒤쪽**의 물체는 제외 |
| 애매 판정 | 4° | 1등과 2등의 각도 차가 4° 미만이면 **"둘 중 뭘 말하는지 모르겠다"** 로 처리 |

마지막 항목이 중요하다. 근소한 차이를 억지로 하나 고르지 않고 **애매함을 표시**한다
(HUD에 "two tools too close to call - move your hand"). 잘못 집는 것보다 되묻는
것이 낫다는 원칙이다.

또한 모든 후보의 각도를 `info["scores"]`로 함께 반환한다 — **왜 그것을 골랐는지
화면에 보여줄 수 있어야** 신뢰·디버깅이 가능하기 때문이다. HUD에 각 공구마다
`HAMMER -44deg` 같은 값이 뜨는 근거가 이것이다.

### 2.3 손떨림 억제 — `PointingSmoother`

프레임마다 독립적으로 고르면 손이 숨 쉬는 것만으로 하이라이트가 깜빡인다.

- 도전자가 **연속 4프레임** 앞서야 선택을 교체한다 (`switch_frames=4`)
- 손이 한두 프레임 사라져도 **1.0초** 동안은 직전 선택을 유지한다 (`hold_seconds=1.0`)

의도적인 이동에는 지연을 거의 주지 않으면서 떨림만 제거한다.

### 2.4 가리킨 "지점" — 광선-평면 교차와 조준 평면

물체가 아니라 **작업 부위**를 가리킬 때는 검출된 객체가 없다. 이때는 광선을
수평 평면과 교차시켜 3D 점 하나를 만든다 (`ray_plane_point`).

```
t = (plane_z − origin_z) / d_z
p = origin + t·d          # t ≤ 0 (뒤쪽) 이거나 t > 1500 mm 이면 거부
```

**조준 평면(AIM PLANE)** — 실측으로 드러난 문제와 그 해법:

평면을 항상 테이블(z=0)로 두면, 높이가 있는 대상(예: 컨베이어 옆면 60 mm)을
가리켰을 때 광선이 그 위를 스쳐 **뒤쪽 바닥**에 꽂힌다. 실측 오차:

| 조준 평면 | 계산된 지점 | 실제 지점과 오차 |
|---|---|---|
| 0 mm | (440, −45, 0) | **65 mm** |
| 30 mm | (430, −52, 30) | 32 mm |
| **60 mm** | (420, −60, 60) | **0 mm** |
| 90 mm | (410, −67, 90) | 32 mm |

그래서 평면 높이를 실행 중에 `,` / `.` 키로 10 mm 단위 조절하게 했다. 마크는
광선을 따라 미끄러지므로, 화면을 보며 대상 표면에 붙을 때까지 올리면 된다.

### 2.5 광선을 "광선처럼" 보이게 — 종단과 스냅

- **종단**: 광선은 무한히 뻗지 않고 **처음 만나는 물체**에서 끊긴다. 물체까지의
  거리 `hit`가 평면까지의 거리 `reach`보다 짧으면 거기서 자른다.
- **스냅**: 물체가 확실히 선택되면 마크를 평면 교차점이 아니라 **그 물체의 3D
  위치**에 붙인다. 빈 작업대를 가리킬 때만 평면 교차점을 쓴다.
- **공중의 물체**: 파지용 3D 목록은 "테이블 위 12 cm 이내"로 제한돼 있어
  **손에 든 물건이 목록에서 빠지는** 문제가 있었다. 가리키기 전용 상한
  `POINT_TARGET_Z_MAX_MM = 600 mm`을 따로 두어 해결했다. 파지 경로의 게이트는
  그대로 유지된다(공중의 물건을 집으러 가면 안 되므로).

### 2.6 선택이 곧 목표 전환

가리켜서 확정된 클래스는 `set_target(..., quiet=True)`로 로봇의 목표가 된다.
단, **IDLE / ERROR / DETECT / ARMED** 상태에서만 바뀐다 — 접근이 시작된 뒤에
목표가 바뀌면 이미 다른 물체를 향해 계산된 자세로 팔이 날아가기 때문이다.

## 3. 기능 A — 손에서 받아 빈 곳에 놓기

### 3.1 전체 시퀀스

```
홈 복귀 → 그리퍼 열기 → 손 안정 대기 → 손 위 130 mm 호버
→ 손목 카메라로 물체 상단 측정 → 재안정 확인 → 천천히 하강
→ 파지 → 들어올림 → 폭 확인 → 빈자리 탐색 → 내려놓기 → 홈 복귀
```

구현: `webcam_pick_place.py`의 `handle_take_from_hand()` → `_job_take_from_hand()`

### 3.2 사람 손 위로 내려가기 위한 안전 설계

사람의 손 위로 로봇을 내리는 동작이므로 일반 파지와 다른 기준이 적용된다.

**(a) 그리퍼를 먼저 연다.** 사람에게 접근하기 전에 연다 — 접근 후에 열면
손 바로 위에서 손가락이 벌어진다.

**(b) 손이 멈췄는지 통계로 판정** (`_steady_palm`)

원시 3D 좌표는 절대 정지하지 않는다(작업대에 얹은 손도 비전 지터가
40~80 mm/s). 그래서:

- 최근 **0.8초** 창의 좌표들을 모으고
- **중앙값**을 기준점으로 삼은 뒤
- 중앙값으로부터의 거리 분포에서 **80 백분위수**를 "흔들림"으로 정의
- 이 값이 **25 mm** 미만이어야 "멈췄다"고 인정

최댓값이 아니라 백분위수를 쓰는 이유는 한 번의 튀는 값에 판정이 파괴되지
않게 하기 위해서다.

**(c) 손바닥이 곧 바닥이다.** 일반 파지는 테이블을 기준면으로 쓰지만, 여기서는
손바닥이 기준면이다. 손목 D435i로 물체 상단을 측정해
`grasp_z = 상단 − 35 mm`로 잡되, **손바닥 + 18 mm** 아래로는 절대 내려가지
않는다. 물체를 인식하지 못했을 때는 높이를 추측하지 않고 손바닥 + 28 mm에서
"조심스럽게" 잡는다.

**(d) 하강 중 손이 움직이면 중단.** 하강 직전 한 번 더 안정성을 확인하고,
직전 위치에서 **35 mm** 이상 벗어났으면 다시 호버로 물러났다가 재시도한다.

**(e) 속도를 낮춘다.** 접근은 평소의 **60%**, 하강·상승은 **35 mm/s**.
사람 위에서의 속도는 안전 여유이자 심리적 안심의 문제다.

**(f) 실제로 잡았는지 확인.** RG2 그리퍼의 `get_width()`로 폭을 읽어
**12 mm 미만**이면 "아무것도 안 잡혔다"고 판단하고 물러난다. 빈 그리퍼로
빈자리에 가서 놓는 시늉을 하는 것을 막는다.

| 상수 | 값 |
|---|---|
| `TAKE_HOVER_MM` | 130 mm (손 위 호버 높이) |
| `TAKE_MIN_ABOVE_PALM_MM` | 18 mm (손바닥 최소 이격) |
| `TAKE_STABLE_WINDOW_SEC` / `RADIUS_MM` | 0.8 s / 25 mm |
| `TAKE_ABORT_MOVE_MM` | 35 mm |
| `TAKE_DESCEND_VEL/ACC` | 35 / 35 |
| `PLUNGE_MM` | 35 mm (물체 상단 아래로 파고드는 깊이) |
| `TAKE_TIMEOUT_SEC` | 45 s |

### 3.3 "빈 곳"을 찾는 알고리즘 (`find_free_spot`)

"아무 데나 놓아줘"는 사람에게는 쉽고 로봇에게는 여러 조건의 동시 만족 문제다.

작업 영역을 **45 mm 격자**로 훑으며 각 후보 셀에 대해:

1. **도달 가능성** — 베이스로부터 거리가 260~890 mm 범위
2. **가장자리 여유** — 작업 영역 경계에서 90 mm 안쪽
3. **기존 물체와의 간격** — 가장 가까운 물체까지 **170 mm** 이상
4. **사람과의 간격** — 손 위치로부터 **320 mm** 이상
5. **점수화**

```
score = min(gap, 340 mm) − 0.35 × travel
```

여기에 두 가지 설계가 들어 있다.

- **첫 번째로 찾은 빈칸을 쓰지 않는다.** 래스터 스캔의 첫 빈칸은 항상 구석이고,
  구석은 공구를 두기에 가장 쓸모없는 자리다. 그래서 전수 탐색 후 점수 최대를
  고른다.
- **여유는 상한을 둔다** (`clearance × 2`). 넓을수록 좋지만 무한정 좋지는 않다.
  일정 이상 넓어지면 점수가 더 오르지 않으므로, 남은 후보들 사이에서는
  **이동 거리**가 결정한다. 아무 이유 없이 작업대를 가로지르는 것은 느리고,
  옆에 서 있는 사람에게 위협적이다.

검증: 3,876가지 조합(물체 배치 × 사람 위치)에 대해 전수 시험, **안전 위반 0건**.

### 3.4 자연어 연결

`unified_copilot/intents.py`가 "내 손 위에 있는 거 다시 가져다 놓고",
"이거 가져다 놔" 등을 `ROBOT_SKILL/TAKE_FROM_HAND`로 분류하고,
`ros_bridge.send_take_from_hand()`가 ROS 토픽으로 전달한다.

`robot_skills/take_from_hand.py`는 로봇의 상태 문자열을 사람이 들을 말로
바꾼다(예: 손이 계속 움직이면 "손을 잠깐 멈춰 주세요"). 실패 코드도
`HAND_NOT_STABLE`처럼 구분해 전달한다 — 로봇 문제인지 판단 문제인지
작업자가 알아야 하기 때문이다.

복합 명령 **"이거 가져다 놓고 저거 가져와"** 는 `TAKE_THEN_FETCH`로 분류되어,
첫 작업이 **실제로 끝난 뒤에** 두 번째가 시작된다(물리 스킬은 설계상 한 번에
하나만 실행된다).

## 4. PPT용 요약 포인트

**손가락 레이저 타겟팅**
1. 검지 두 관절(5번·8번)을 각각 삼각측량 → 3D 광선
2. 매칭 기준은 **거리가 아니라 각도** (22° 콘) — 사람이 제어하고 관찰하는 양
3. 1등·2등 각도 차 4° 미만이면 **판단을 보류**하고 되묻는다
4. 연속 4프레임 우세해야 선택 교체 — 떨림 제거, 의도적 이동에는 지연 없음
5. 조준 평면 높이 조절로 **높이가 있는 표면**도 정확히 지목 (오차 65 mm → 0 mm)
6. 광선은 첫 물체에서 **끊기고**, 선택된 물체에 마크가 **달라붙는다**

**손에서 받아 정리하기**
1. 사람 손 위 동작 — 그리퍼 먼저 열기, 60% 속도, 하강 35 mm/s
2. 정지 판정을 **중앙값 + 80 백분위수**로 — 한 번의 튀는 값에 무너지지 않음
3. 손바닥을 기준면으로, **손바닥 + 18 mm** 아래로는 불가
4. 하강 중 손이 35 mm 움직이면 **중단 후 재시도**
5. 그리퍼 폭 12 mm 미만이면 "못 잡았다"로 판정 — 빈손으로 놓는 시늉 방지
6. 빈자리는 **점수 기반 전수 탐색**: 물체 170 mm·사람 320 mm 이격, 여유는
   상한을 두고 그다음은 이동 거리로 결정 (3,876조합 검증, 위반 0건)

**공통 설계 철학**
- 삼각측량마다 **worst-gap 정직성 지표**를 함께 계산하고, 신뢰할 수 없으면 버린다
- 애매하면 고르지 않고 **되묻는다**
- 판단 근거(각도·간격·이유)를 항상 **화면에 노출**한다
